A structured route from instruction to interaction.

Robot demonstration collection is often bottlenecked by manual affordance labeling, task-specific reward design, and brittle planning. LADDER makes the intermediate structure explicit so that the simulator can execute and verify the resulting plan.

The problem

Collection pipelines need more than a robot and a scene.

Large-scale synthetic data is useful only when the robot can repeatedly reach the functional part of an object, execute the intended interaction, and retain trajectories that satisfy task criteria.

  • Manual affordance annotations do not scale with asset libraries.
  • Reward shaping and skill learning add a task-by-task cost.
  • Language-only plans can miss object identity and geometry.
The idea

Represent the interaction before planning the motion.

LADDER encodes each asset as a parameterized instance, formulates affordances as functions of geometric and kinematic parameters, and maps those affordances to the live scene before motion planning.

  • Continuous feasible pose regions replace isolated labels.
  • Asset IDs keep repeated objects unambiguous.
  • Waypoints connect semantic interaction points to execution.

Five steps, one collection loop.

The workflow separates semantic reasoning from geometric execution, while keeping a structured configuration as the interface between the two.

01

Knowledge construction

Build parameterized instances from geometric primitives and kinematic parameters; derive affordance regions and functions.

02

Task decomposition

Asset and planning agents extract categories and affordances, match them, order atomic tasks, and repair invalid plans.

03

Scene construction

Import category-matched assets into Isaac Lab and randomize pose, appearance, lighting, camera, mass, and friction.

04

Affordance grounding

Use the target asset’s live 6D pose to transform an affordance region and expand it into contact and motion waypoints.

05

Task execution

Plan collision-aware trajectories with CuRobo, execute gripper commands, verify success, and record the demonstration.

Designed for verification and reuse.

The method exposes the interfaces that matter for scalable collection: what the language workflow emits, what the knowledge base supplies, and what the execution loop records.

Structured outputTask name, asset categories, unique IDs, affordance atoms, parameters, and execution order.
Local validationCategory membership, affordance compatibility, ID references, unused assets, and bimanual simultaneity.
Motion groundingApproach, contact, gripper, retreat, hinge-arc, and slider waypoints derived from live object poses.
Collision handlingSimulator collision geometries are converted into obstacles; grasped parts are treated as attached links after contact.
Recorded signalsProprioception, end-effector poses, gripper states, and camera observations for downstream training.
Evaluation boundaryPrivileged simulator state is used to generate demonstrations; learned policies are evaluated from benchmark observations.
Research overview

LADDER connects language-level task structure with geometry-aware robot execution so that successful simulation rollouts become reusable supervision for policy learning.
